STW Divide and Conquer

A server-authoritative strategic campaign system that simulates faction ownership, front movement, strategic locations, and CQB or Stronghold confrontations.

How the campaign works

Divide and Conquer divides detected land into hexagonal cells. Cells belong to RED, BLUE, or remain unconquered. The server advances the front at configurable random intervals and resolves unattended battles using tile strength and campaign events.

BLUE

RHS_USAF, falling back to US.

RED

RHS_AFRF, falling back to USSR.

Diagnostics

Green indicates detected strategic locations. The ownership overlay uses blue and red.

Server only: scans, token decisions, ownership changes, and configuration loading happen on the server. Clients receive the replicated campaign state.

Strategic tokens

CQB and Stronghold tokens are reserved for strategic locations with suitable buildings. Divide and Conquer selects the location and faction; STWCQB and STWStronghold perform their own validation, generation, spawning, and cleanup.

TokenUseFaction composition
CQBVillages, towns, cities, and other eligible settlement areas.Configurable faction bias.
StrongholdLarge suitable buildings, airports, and configured military locations.100% the deploying faction.

A token is placed in enemy or unconquered territory at the front. Deep strategic placement is possible through deepStrategicTokenChancePercent. If a location is rejected by CQB or Stronghold validation, the token is not consumed and another candidate is tried later.

TTL and Game Master deletion

  • When a token reaches strategicTokenLifetimeSeconds without player resolution, the deploying faction wins the cell.
  • When the Game Master deletes an AI Stronghold dummy, the Stronghold and confrontation are removed without awarding the cell.
  • Recently released cells enter a temporary cooldown to prevent immediate redeployment at the same location.
  • AI generated Strongholds have a controlling dummy and remain represented in the entity list.

Recommended companion: STWCombatKnowledge

For the best experience, run STW Divide and Conquer together with STWCombatKnowledge. Divide and Conquer can start without it, but the campaign's strategic CQB and Stronghold encounters work substantially better when CombatKnowledge is enabled.

STWCombatKnowledge provides the shared perception and combat-awareness layer that helps spawned forces respond coherently to nearby players, units, and combat activity. This makes frontline confrontations feel more alive and improves the quality of tactical reactions inside campaign-generated encounters.

Load STWCombatKnowledge on both the server and clients alongside Divide and Conquer, and keep both mods updated to compatible versions. CombatKnowledge is recommended, not a hard requirement for the campaign to start.

For CombatKnowledge setup and behavior settings, see the STWCombatKnowledge manual.

Configuration

Basic ownership persistence is stored separately at $profile:STW/Persistence/DivideAndConquer/STW_DivideAndConquerOwnership_<map signature>.json. It restores only Red and Blue cell ownership. Active tokens, confrontations, timers, and events restart with the server.

The file is generated at $profile:STW/DivideAndConquer/STW_DivideAndConquerCampaignConfig.json. Delete or edit it, then restart the server to apply structural changes.

Use redCQBOwnFactionMinimumPercentage, redCQBOwnFactionMaximumPercentage, blueCQBOwnFactionMinimumPercentage, and blueCQBOwnFactionMaximumPercentage to control per-zone variation. redCQBCombatStrengthFactor and blueCQBCombatStrengthFactor control the relative compensation.

Strategic Stronghold profile: each generated Stronghold samples its buildings, units, patrols, and shooters from the configured minimum and maximum ranges. Roof and tower shooters remain enabled for strategic Strongholds. The sampled values are fixed for that Stronghold encounter.
Strategic CQB: each token receives random occupation time and kill requirements from the configured ranges. Its faction percentage is also randomized per zone. Strategic Stronghold: each token receives a random lifetime and a random soldier-loss defeat percentage when deployed. These values remain fixed for that encounter.

Testing and logs

Use short values such as a 120-second token TTL for testing. Watch the Workbench script.log for messages such as Activated ... token, Strategic token expired, Cell ... transferred, and Stronghold dummy deleted.

When a token is released, another eligible location may receive it after the coordinator refresh interval. A nearby new hexagon can therefore appear shortly after the original one disappears.

Performance: required scanner caches are generated or loaded before strategic processing. Avoid short production intervals because they intentionally create frequent front, token, and event activity.
