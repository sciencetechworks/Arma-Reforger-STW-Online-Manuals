How to read the catalog

Provider

Owns a complete gameplay loop: it can start and operate without VVV. Examples: STWSnipers, STW Anti-Air Team, STW Combat Zone and STW Bases.

Shared API

Defines a neutral contract. It does not create the gameplay by itself. STW Combat Support API is the shared request/provider contract used by support features.

Soft companion

Optional source content or behavior. The provider detects it and adds the capability when available; the base provider continues safely without it.

Bridge / adapter

Connects two providers. It must be installed deliberately because it is useful only when both sides of its contract are present.

Support and awareness graph

This is the important relationship behind Combat Zone and Anti-Air Team. Combat Knowledge can observe eligible AI reports, decide whether support is appropriate, and submit a request through the shared API. The support provider still owns the final validation and execution.

Key distinction: Combat Knowledge decides from information it genuinely received; Combat Zone creates and manages a zone; the adapter is what connects those two. None of this requires the VVV campaign.

STW Anti-Air Team: administrator view

Anti-Air Team does not need VVV, Combat Zone or Combat Knowledge to create pairs. Its automatic system discovers terrain, deploys pairs, replaces casualties and can relocate survivors. Optional content is detected through available prefabs; missing RHS or Glock content affects only those loadout choices. Its declared required core content must still be installed as documented by the Anti-Air manual.

STW Combat Zone: administrator view

Combat Zone is also independent of STWCQB and STWDAC. It represents an active area, maintains a moving bubble around players, spawns groups outside the bubble, dispatches them toward it, and cleans up after the player group leaves.

  1. Standalone/manual: load STW Combat Zone and use its Game Master placement.
  2. Automated support: load STW Combat Support API, STW Combat Knowledge and STW CombatZoneCKnowledgeAdapter on server and clients.
  3. Decision flow: Combat Knowledge evaluates a real sighting; the adapter submits a capability request; Combat Zone validates faction, duplicate zones and provider limits; the server creates or updates the zone.
  4. VVV relationship: none is required. VVV/D&C can coexist, but Combat Zone is not the same thing as strategic CQB.
